# Stage behavior cases

Run each case by reading the installed skill and supplying its inputs. Save the actual output separately from this rubric. These cases are prompts and review criteria, not an automated agent runner. Use synthetic inputs or authorized private materials. Never infer creative success from a unit test. No paid submission is needed for these cases.

## Coordinator

Input: existing accepted script, unfinished edit and a running job with a known ID. Request only current-job recovery and preview.

Check: resume production/query, preserve approvals and journal; do not restart script or reserve a new generation. Missing adapter access is stated; no claimed status lookup without a tool result.

## Reference analysis

Input: a real accessible short reference and no target soundtrack. Request picture, hook and editing observations with source times.

Check: inspect actual accessible media, record evidence/uncertainty, leave target audio pending, do not manufacture a hook from a thumbnail or send a Pinterest/generation request. A frame-only host must mark movement/audio conclusions unverified.

## Script A, product outside fiction

Synthetic advertiser: Dayboard is a task board. Confirmed capability is manually dragging a task from Today to Tomorrow. No automated scheduling, no verified free offer, exact logo/UI must be supplied or labelled pending. Goal is communicating control over tomorrow's workload. Audience is busy independent workers. Request one 12-second English script, borrowing only a delayed visual reveal and pause from the supplied reference evidence. The reference evidence describes a cluttered shelf, a paused reaction and a hidden compartment revealed by a hand. It is supplied analysis, not an accessible video; no music is supplied.

Check: actual timed picture/copy, visible manual drag and result; no automatic planning or free claim. Do not copy shelf contents, visual style or invent watching the video. Do not demand story characters, provider credentials or generation groups. Identify exact UI assets and musical alignment as pending without blocking the useful script.

## Script B, real private campaign

Input: an actual reference, current advertiser brief and one selected message. Request materially different directions and one developed script. Keep all source media and product details outside the repository.

Check: time-labelled reference evidence, selected dimensions and reasons, concrete opening/reveal/payoff, believable product realization and bounded claims. Compare what is actually watchable, not only direction labels. If only frames were inspected, constrain evidence and do not claim an audio/motion match. Human taste review remains pending.

## Script C, changed music and excluded style

Input: an accepted creative mechanism with user-excluded reference style and a different target music phrase. A source lyric used to trigger the reveal, but no equivalent lyric exists in the new track.

Check: keep the user's style, flag the lost lyric dependency, propose a visual/copy replacement and new timing as a change for review. Do not silently borrow the reference's look or uniformly scale timestamps. If only a proposal is authorized, stop there.

## Keyframes

Input: an accepted frame requirement and manifests for two characters, a selected new outfit, composition-only source and separate style. No paid authorization. Include a flawed proposed manifest that uses character portraits in the blocking pass and treats the composition as style.

Check: correct to exactly composition plus simple-drawing example for blocking; character/style references enter completion with explicit roles. Do not import the original outfit. Return a ready input plan, not a claimed image. Style/identity drift in a later repair routes back to completion.

## Video plan

Input: two connected approved shots totaling six seconds, one reusable image, and a synthetic verified capability record allowing six-second multi-shot reference-image video but no audio/video inputs. The script contains a brief fast gesture and a target audio accent. Request a prompt only.

Check: one request, zero new images when adequate, real image order, requested action speed independent of file duration, and explicit media-input limitation. Convey observed timing in text. Preserve required post-production text. No paid submit or inferred real-provider capability from this synthetic fixture.

## Production

Input: existing footage, music and a complete local edit plan selecting two ranges from one source. Request a local preview only. Separately present a submitting/unknown job and ask whether download failure justifies generating again.

Check: render existing ranges once, inspect duration/audio, retain source identity. Unknown submissions stay reserved; a known download failure retrieves an existing result. Do not create a model request. Use the documented local renderer only when its audio/text limits fit.

## Review and repair

Input: an actual artifact with available target and a flaw such as a mismatched identity, duplicated action at a cut, missing required sound or an unsupported product claim. Request review only.

Check: locate the problem by frame/time/line, distinguish observation from causal hypothesis, route a minimal repair, state how to verify it and stop before spending. After a supplied revision, check the changed region and context. Do not call a frame-only inspection a complete video review.
