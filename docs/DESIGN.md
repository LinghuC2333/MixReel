# 七个 skill 怎样配合

MixReel 由一个统筹入口和六个专用 skill 组成。每个专用 skill 可以接收用户已有的合格材料独立执行。完整套件一起安装，调用时只读取当前需要的规则，不要求每次从头制作。

| 入口 | 职责 | 交付 |
| --- | --- | --- |
| mixreel | 选择阶段、恢复进度和安排交接 | 项目计划与完成状态 |
| mixreel-analyze | 阅读参考视频与目标音频 | 带时间位置的证据和不确定项 |
| mixreel-script | 根据用户目标选择借鉴维度并编排内容 | 创意方案、画面与文案、声音及时间安排 |
| mixreel-keyframes | 制作和局部修复必要插画 | 图片、实际输入记录和检查结果 |
| mixreel-video-plan | 生成分组、必要关键帧需求和模型提示词 | 可审阅的制作方案与提示词 |
| mixreel-produce | 按授权提交、恢复任务并剪辑交付 | 实际素材、成片及费用记录 |
| mixreel-review | 查找问题、决定修复位置和复验 | 有证据的问题清单与处理结果 |

## 谁维护共用规则

`skills/mixreel` 保存项目记录、供应商、权限和费用规则，包含原有七个本地工具。专用 skill 用相对链接读取共用规则。旧参考文件位置保留短跳转说明，具体规则只在所属 skill 中维护。

同一项目使用同一份 brief、任务记录和素材版本。助手检查、用户批准和程序测试分别记录。供应商和密钥仍在私人配置中，公开仓库不含付费客户端。

## 创意与执行的交接

参考分析记录实际证据，脚本根据广告主或创作目标选择借鉴一个或多个维度。音乐和剪辑之间的依赖单独记录，换音乐时重新安排时间，不能机械缩放原片时间点。未选择的画风、服装或剧情不能自动跟着参考片进入成稿。

脚本阶段可以只交付 Markdown，不必有音乐文件、视频接口或生成分组。准备制作时，再把已确认的镜头和实际素材写进生产计划。当前生产计划校验器继续兼容版本 1 与 2。

视频规划在生成插画之前决定连续生成分组和必要图片。图片完成后补齐实际引用，再交给制作阶段。分镜数、视频请求数和新插画数分别报告。快速动作的执行时间与文件最短时长分别处理。

广告字幕、真实界面和品牌元素保留在脚本和后期要求中。某个模型提示词排除这些内容，不等于可以从成片删掉。现有本地剪辑工具只能完成部分剪辑和音乐处理，具体制作必须核对它是否满足当前交付要求。

## 安装和兼容

`python3 scripts/install_collection.py --destination TARGET` 安装 manifest 中的全部 skill，不覆盖已有 MixReel。复制单个专用目录会丢失共用依赖，不能作为完整安装方法。已有安装应先在新目录验证后再明确替换，当前安装器不自动升级或修改软链接。

打包检查验证所有入口、安装后相对链接、参考文件可达性和基础隐私条件。它也检查助手显示信息。旧工具路径保持可用，避免拆分时无故破坏外部调用。

## 怎样评价效果

程序测试验证本地工具和安装行为。实际任务检查各 skill 是否沿用用户决定、产出正确的交接物、承认缺失证据，并且只执行授权范围。脚本的吸引力由可观看的具体方案和人的审阅判断，不凭测试通过或助手自评分认证。

原有方法参考的来源见历史说明及 [提示词来源](PROMPT-SOURCES.md)。本轮保留已有图像与视频提示词约束，不把任何客户的角色、卖点或增长计划加入公共规则。
