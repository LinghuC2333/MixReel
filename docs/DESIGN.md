# 设计与取舍

## 一个入口，按需读到细节

这个项目服务同一类任务，从参考视频的情绪和镜头安排出发，用新的故事与音乐制作短片。提案、插画、动画和剪辑共享已确认的决定，因此先保留一个入口。各阶段说明独立存放，执行到哪一步才读取哪一部分。

只有当某一阶段具有独立使用需求、独立输入输出和稳定的维护者时，再拆成单独 skill。当前不引入多层调度器，也不强制多助手协作。

## 采用的结构

| 来源中的思路 | 本项目中的用法 | 保留的边界 |
|---|---|---|
| HyperFrames 先看当前产物再决定下一步 | 先读取项目记录，再从受影响的阶段继续 | 不引入其渲染框架或默认产品选择 |
| HyperFrames 按需加载专业说明 | 入口按任务阶段链接参考文件 | 不为了层级而新增独立 skill |
| Superpowers 用真实失败检查规则 | 将失败变成可观察的测试题，与无 skill 对照 | 不强制照搬禁令、子助手或固定测试次数 |
| Superpowers 简短的技能描述 | 描述写触发条件，执行细节放正文 | 不把全部工作流程塞进发现阶段 |
| 逐镜画面描述先于生成 | 保留单一主要机位、可见动作与反应、道具状态和环境声 | 模型参数、风格、时间表放在相邻字段 |
| 已验证的图片和视频工具经验 | 按参考图用途、能力和失败症状选择方法 | 不固化品牌、历史单价和一次测试的结论 |

公开结构参考为 [HyperFrames](https://github.com/heygen-com/hyperframes) 和 [Superpowers](https://github.com/obra/superpowers)。本项目的说明与脚本重新撰写，没有复制这两个项目的实现代码。

## 把审美判断写成可以检查的产物

候选故事需要给出原著出处、当时的关系状态、观众能看见的阻碍以及结尾留下的感觉。评分不能替代这些依据。

分镜需要写明人物位置与视线，动作怎样发生、镜头怎样移动、最后落在哪里。机器检查时间与引用；创作审阅判断画面是否有张力。这两种检查分别记录。

素材不足时先确定缺少的内容，再搜索构图。镜头数量由新音乐和动作可读性决定，原视频的镜头数只作为参考。

## 在少数关键产物上协作

默认协作顺序为故事与逐镜方案、代表帧画风、整组关键帧与视频预算。已获授权的范围不重复询问。用户明确授权自主选择时，记录助手的决定与理由，不冒充用户确认。

批准记录绑定具体版本。换音乐需要重新检查时间和剪辑；只修一只手通常影响那张图及其后续片段。变化影响不到的决定继续有效。

## 接口和费用单独维护

主流程只要求明确的能力，例如图像编辑、区域控制、参考图动画、任务查询。具体供应商的参数、报价方式和参考图限制放在项目接口记录中，使用前按当前文档核实。

附带的本地记录工具在提交前预留预算，将生成、下载和费用核对分开。提交结果未知时保留预算，不自动补交。这个工具不直接提交任务，也不能代替宿主的权限控制。

诊断脚本给出切镜、能量变化和画面变化的候选位置。它们不自动断定乐句起点或剧情高潮，相关位置仍需结合音画确认。

## 模型写法与本机配置

可编辑的场景描述保留通用创作信息。Seedance 2 与 H3 的最终提示词分别读取对应参考文件，H3 直接从已批准的场景和有序参考图生成，不经过 Seedance 格式转换。这样可以保留各自的表达要求，同时不改变已批准的故事和镜头。

用户的服务配置和密钥保存在源码外。公开包提供空白模板与初始化工具，实际服务调用仍交给宿主工具或用户配置的程序。详细规则见本机配置说明。

## 开源边界

公开包保留通用方法、合成示例和测试。客户项目复盘、源素材、模型账户配置及付费记录均保留在外部项目目录。已有的私人辅助 skill 不是安装依赖。
