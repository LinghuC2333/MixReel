## 当前组成

当前只有 `skills/mixreel/SKILL.md` 一个 skill 入口，包含 14 份参考规则、7 个本地 Python 工具、4 份素材模板和一份助手显示配置。仓库另有 6 个测试文件，共 65 项测试。

## 必须处理的依赖

1. `scripts/check_package.py` 固定检查单个 `skills/mixreel`，要求名称为 mixreel，并要求每份参考文件直接出现在该入口中。多 skill 结构需要重新定义发现、引用和完整性检查，不能只移动文件。
2. 六个测试文件都直接引用当前 skill 下的工具或素材路径。`render_edit.py` 从相邻目录加载 `validate_plan.py`，`init_config.py` 从上一级 skill 的 assets 读取模板。共享目录迁移必须同时检查这些依赖。
3. 两份 README 当前支持复制单个 `skills/mixreel` 安装。拆分后须验证完整安装和单独调用的区别，保证安装产物带有必要共用文件。此次尚未选择或实测新的安装方式。
4. `plan.json` 版本 2 要求音乐、生成分组、关键帧设计及制作审阅状态。只分析参考或只写脚本时，不应为了通过完整制作校验而编造这些内容。后续需明确阶段交付物及进入制作计划的转换时机，并保留旧计划兼容性。
5. `motion-edit.md` 同时包含规划、执行和审片，`storyboard.md` 同时包含面向用户的脚本和模型交接。按职责迁移时需要明确唯一维护位置，防止不同 skill 对同一件事给出相反要求。
6. 现有模型提示词规则把字幕、标识和其他精确可读元素排除在部分生成提示词之外；广告脚本仍需能表达这些元素，并标明后期或真实界面素材的实现方式。当前剪辑工具只输出音乐，丢弃源视频声音，也不负责字幕和界面叠加。后续不能把它宣称为完整广告合成工具。
7. `docs/DESIGN.md` 仍说明采用单入口；README 的目录说明、`docs/MIGRATION.md`、`docs/PROMPT-SOURCES.md` 的文件位置、`docs/VALIDATION.md` 与 `evals/README.md` 也需要在真正拆分时同步核对。

## 必须保留的行为

生成方案先于插画，镜头数、视频请求数和新插画数分开记录。连续动作优先组织为模型实际支持的连续生成请求，不能在提示词整理时偷偷退回逐镜付费生成。快速动作的执行时间不能被文件最短时长拉长。

每张必要的新插画保留现有默认四步流程。输入图片的构图、身份、服装和画风角色继续依据用户已经确认的决定；直接编辑参考帧的条件不能丢失。

H3 和 Seedance 的写法按选定模型读取。H3 保留六段格式、参考顺序及动作连续性，不能使用 Seedance 成稿作为中间稿。上述写法均不能被当成已验证的接口能力。

同一项目共用一份预算和任务记录。结果未知的提交不能自动重试，下载失败不能重新生成。每个 skill 独立调用时仍须遵守已有授权，记录助手判断与用户确认的区别。
